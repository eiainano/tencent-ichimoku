# tencent-ichimoku

港股日线的一目均衡表（Ichimoku Kinko Hyo）诊断工具。给一个股票代码，拉行情、算四周期指标、打印一份可以直接读的盘后状态表。

写它的原因很简单：市面上的一目图表大多只画「当下」的云，而一目最有用的部分恰恰是**未来 26 根已经被锁定的云**——它不需要预测，是算术。这个工具把这部分单独拎出来，连同四要素打分、金叉时点、价位门槛一起做成文本输出，方便回溯和写进笔记。

```
=== Four timeframes (score 0-4) ===
tf     close   tenkan    kijun    spanA    spanB  cloud     pos  score
D     385.20   404.20   420.70   436.75   458.60   bear   below      0
W     385.20   420.70   437.90   535.36   566.50   bear   below      0
M     385.20   487.77   516.31   307.20   433.09   bear      in      1
Q     385.20   516.31   433.09   298.03   223.53   bull   above      3
```

## 安装

```bash
python -m pip install -r requirements.txt
```

只要 pandas 和 numpy。

## 用法

```bash
# 1. 拉数据（示例数据已附在 data/00700.csv，可跳过）
python fetch_hk_daily.py hk00700 data/00700.csv --skip-today

# 2. 出诊断
python analyze.py data/00700.csv
```

`--skip-today` 会丢掉当天那根未收盘的 K 线。港股收盘竞价（CAS）在 16:00–16:10，16:10 之前抓到的最后一根都是残的。

可选参数：

```bash
python analyze.py data/00700.csv --bars 20 --prices 380 400 420
```

`--bars` 控制未来云的显示长度，`--prices` 指定金叉时点扫描用的假设价位。

## 输出都包含什么

| 段落 | 内容 |
|---|---|
| Bar anatomy | 开高低收、涨跌幅、跳空、振幅、收盘在日内区间的位置、实体与上下影、量比 |
| Four timeframes | 日/周/月/季四周期的一目四要素打分（0–4） |
| Momentum | MACD(12,26,9) 的 DIF/DEA/柱，KDJ(9,3,3) 的 K/D/J/RSV，以及柱状值的路径 |
| Forward cloud | 未来 10–26 根已经被锁定的云：上下沿与厚度 |
| Golden cross timing | 假设价格原地不动，转换线要第几根才能上穿基准线 |
| Score thresholds | 假设价格原地不动，第 N 根要涨到多少分才变成 1/4、2/4、3/4 |
| Position | 250 日区间位置、到四线的距离、在云上/云下已持续多少根 |

四要素打分口径：`收盘 > 云顶` + `先行带A > 先行带B` + `转换线 > 基准线` + `现价 > 26 根前收盘`。

## 实现上几个容易踩的坑

这些是写的过程中真实踩到的，也是这个仓库存在的主要价值。

**1. 腾讯行情接口的字段顺序不是 OHLC**

`hkfqkline` 每行返回 `[date, open, close, high, low, volume, ...]`——第 2 位是**收盘**，不是最高。按 OHLC 读会静默污染整个数据集。`parse_rows()` 里加了 OHLC 顺序校验，就是为了让这个错误当场炸掉而不是几个月后才发现。

**2. 未来云不是预测，是已经算好的**

第 `t` 根画出的云，用的是**原始（未位移）第 `t-26` 根**的值。所以未来 26 根的云完全由今天之前的数据决定。

常见错误是把 `spanA.shift(26)` 这种「已位移序列」的最后 26 行当成未来云——那 26 行其实是**过去 26 根**的云。`future_cloud()` 走的是 `spanA_raw` 的尾部，才是真的投影。

**3. 迟行线用 `shift(-26)` 在最后一行恒为 NaN**

`close.shift(-26)` 的末 26 行是空的，拿它和现价比较永远返回 False，会得到「迟行线永远看空」的假象。正确写法是比较 `close[-1]` 和 `close[-1-26]`。

**4. 价位门槛的映射不是单调的**

价格超过 26 根窗口的高点之后，转换线和基准线会共用同一个高点作锚，两者一起退化。这时候「价格越高分越高」这个假设不成立，用二分法会漏掉真实存在的解。`thresholds()` 用的是 0.05 的网格扫描。

**5. 前复权价格会随分红整体变化**

`qfq` 每次除权都把历史价格重新算一遍，所以不同时间点抓的同一段历史，绝对值会有几个百分点的差异（跨年越久差得越多）。这意味着：**跨快照比指标绝对值是没有意义的，要比就比相对位置**。本仓库的示例数据是 2026-10-27 收盘的快照。

## 文件结构

```
.
├── fetch_hk_daily.py   # 行情抓取：分页、字段校验、盘中数据识别
├── ichimoku_core.py    # 一目计算：原始值/已位移值分离、未来云投影、四要素打分
├── analyze.py          # 诊断输出：把上面两块的结论打印成一张表
└── data/00700.csv      # 示例数据：0700.HK 日线，2004-06 起，前复权
```

`ichimoku_core.py` 是唯一需要 import 的模块，其余两个是命令行入口。

## 关于数据

示例数据来自腾讯公开行情接口，前复权，仅供复现和演示。接口没有文档，随时可能变；也没有任何频率保证，请自行缓存、别刷。
